## 2. 목표 (한 문장)

모바일티켓 · 앱 · 결제 오류 · 입장 장애 및 일반 환불 정책 문의에 공개 지식 문서 근거와 함께 답하고, 근거가 없거나 사람의 판단이 필요하거나 공연 직전이면 개인정보를 조회하지 않는 범위에서 상담원에게 넘긴다.

## 3. 범위

| 앱 · 계정 오류 | 자동 답변 | `app-login-troubleshooting` |

| 환불 안내 · 요청 | 1차 금액 안내 → 고객 확정 후 환불 요청 티켓. 실제 취소는 상담원 | `refund-policy` |

## 4. 규칙

- 공통 계약은 팀장의 허락 없이 바꾸지 않는다.
- 한 사람 = 한 워크플로우 파일. 남의 파일은 말하고 고친다.
- 고칠 때마다 공통 시나리오를 다시 돌리고, 커밋 메시지에 통과 수를 쓴다.
- 키 · 토큰은 Credential에만. 커밋 전 `tscan staged`.
- 81일차 8교시 기능 동결: 그 뒤로는 시험 · 고치기 · 문서 · 발표 준비만. 82일차 11시부터는 워크플로우를 고치지 않는다.
- VM의 공통 폴더와 최종 배포는 팀장이 맡는다 (기본 브랜치에서, 배포 뒤 공통 시나리오). 시험용 자기 워크플로우 파일은 각자 올리되, 올리기 전에 팀 채팅에 알린다.
- `flow.py push`는 공용 n8n을 다시 켜므로, push 뒤에는 `tools/reindex.py`로 색인을 다시 돌린다.
- 막히면 30분 안에 팀에, 1시간이면 강사에게.
