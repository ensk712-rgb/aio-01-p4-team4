# 팀 헌장 · 티켓모아

> 80일차 2교시에 확정하고 `docs/TEAM-CHARTER.md`로 저장한다. 바뀌면 6절에 날짜와 함께 적는다. (2026-11-03 초안, 리드 작성)

## 1. 팀

| 이름 | 역할 (주 담당) | 함께 보는 역할 | 맡는 워크플로우 파일 |
| --- | --- | --- | --- |
| 최두나 | 팀장 (리드 · 통합) | 시연 · 발표 | `ticketmoa-support.json` (병합) |
| 최강현 | 오케스트레이션 | 워크플로우 설계서 2~4절 | `ticketmoa-agents.json`, `ticketmoa-refund.json` |
| 정예진 | RAG | RAG 설계서 | `ticketmoa-index.json`, `ticketmoa-search.json`, `ticketmoa-tech.json`, `knowledge/` |
| 심환석 | 연동 · 안정성 | 워크플로우 설계서 5~7절 | `ticketmoa-payment.json`, `ticketmoa-handoff.json`, `ticketmoa-errors.json`, `data/` |
| 김인혜 | 시험 · 품질 | 실행 결과서 | `cases/`, `requests/`, `runs/` |

## 2. 목표 (한 문장)

모바일티켓 · 앱 · 결제 오류 · 입장 장애 · 환불 문의에 지식 문서 근거와 함께 답하고, 근거가 없거나 돈이 움직이거나 공연 직전이면 반드시 상담원에게 넘긴다.

## 3. 범위

| 처리할 문의 유형 | 처리 방식 | 근거 문서 |
| --- | --- | --- |
| 모바일티켓 · 입장 장애 | 자동 답변, 공연 직전이면 긴급 이관 + 현장 알림 | `mobile-ticket-troubleshooting`, `onsite-entry-fallback` |
| 앱 · 계정 오류 | 자동 답변 | `app-login-troubleshooting` |
| 결제 오류 | 안내 후 항상 이관 | `payment-error-guide` |
| 예매 조회 | 본인 건만 자동 답변, 남의 건은 권한 없음 | (예매 기록) |
| 환불 안내 · 요청 | 금액 안내 → 고객 확인 → 티켓 이관. 30만원 초과 · 당일은 바로 이관 | `refund-policy` |
| 부정 예매 · 암표 | 제한 사유는 자동 답변, 암표 신고는 이관 | `fair-booking-policy` |
| 일반 정보 | 자동 답변 | `venue-faq` |
| 불분명한 문의 | 보완 질문, 3회째 이관 | — |

하지 않을 것 (범위 밖): 실제 환불 · 결제 취소 실행, 실제 Slack · Jira · 메일 발송, 로그인 · 세션, 다국어.

## 4. 규칙

- 공통 계약은 팀장의 허락 없이 바꾸지 않는다.
- 한 사람 = 한 워크플로우 파일. 남의 파일은 말하고 고친다.
- 고칠 때마다 공통 시나리오를 다시 돌리고, 커밋 메시지에 통과 수를 쓴다.
- 키 · 토큰은 Credential에만. 커밋 전 `tscan staged`.
- 81일차 8교시 기능 동결: 그 뒤로는 시험 · 고치기 · 문서 · 발표 준비만.
- VM에는 팀장만 배포한다 (기본 브랜치에서, 배포 뒤 공통 시나리오).
- 막히면 30분 안에 팀에, 1시간이면 강사에게.
