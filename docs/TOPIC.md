## 1. 주제 한 줄

"온라인 티켓 예매 플랫폼 티켓모아의 예매 고객을 위한 모바일티켓·결제·입장 기술지원 자동화"

목표 한 문장: 가상의 티켓 예매 기업 티켓모아의 고객센터로 들어오는 모바일티켓·앱·결제 오류·입장 장애 문의를 자동 분류하고, 지식 문서와 예매 조회로 해결 방법을 안내하며, 해결이 어렵거나 환불처럼 사람의 승인이 필요한 건은 요약해 상담원에게 티켓으로 넘긴다. 입장 장애 때는 승인된 대체 입장 방법을 먼저 안내한다.

입구·뒷단 조합: **A 기본형** (팀 웹훅 `ticketmoa-support` + 연습용 데이터 API). 공통 시나리오가 모두 통과한 뒤 직원용 웹 화면을 팀 웹훅 앞에 붙여 시연 보조로만 쓴다 (가산, 평가 기준은 A 그대로).

## 3. 범위

| 문의 유형 (4~6개) | 처리 방식 (자동 답변 / 보완 질문 / 항상 이관) | 근거 문서 |
| --- | --- | --- |
| 모바일티켓·입장 장애 (QR이 안 떠요, 게이트 인식 실패) | 자동 답변. 공연 직전·전체 장애는 긴급 이관 + 현장 알림 | `mobile-ticket-troubleshooting`, `onsite-entry-fallback` |
| 앱·계정 오류 (로그인 반복, 인증 문자 미수신) | 자동 답변 | `app-login-troubleshooting` |
| 결제 오류 (결제됐는데 예매 없음, 이중결제) | 예매 조회 + 안내 후 항상 이관 | `payment-error-guide` |
| 예매 조회 (내 예매 상태) | 자동 답변 (본인 건만, 남의 건이면 권한 없음) | (예매 기록 조회) |
| 환불 안내·요청 | 자동 답변(규정·금액) → 고객 확인 후 환불 요청 티켓으로 이관 | `refund-policy` |
| 부정 예매·암표 (매크로 제한, 해외 IP, 암표 신고) | 제한 사유는 자동 답변, 암표 신고는 항상 이관. 반복 요청·차단 IP는 LLM 앞에서 `차단` | `fair-booking-policy` |
| 의도가 불분명한 문의 | 보완 질문, 3회째 이관 | — |

자동 답변하면 안 되는 경우:

- 돈이 움직이는 처리 (환불 확정, 결제 취소): 고객 확인 후 상담원 티켓으로만
- 환불액 30만원 초과, 공연 당일 취소 요청
- 강한 부정 감정, 고객이 상담원 연결을 직접 요청
- 지식 문서에 근거가 없는 질문
- 현장 스태프 전용 절차를 묻는 일반 고객 질문 (그 문서를 근거로 쓰지 않음)
